# 第 7 层：安全

安全不是某一层的功能，而是横跨所有层的约束：第 1 层的认证鉴权、第 2 层的数据访问、第 4 层的任务执行、第 6 层的日志和 trace，都有安全问题。单独成一层，是为了把攻击面集中起来看。左边是传统应用安全：OWASP Top 10（访问控制、注入、供应链、异常处理……）和数据隐私（PII 的识别、最小化、加密、可删除）。右边是 LLM 带来的新攻击面，根源都是同一件事：**模型会读不可信的输入，而且能调用工具去执行动作**。于是有了 prompt injection（数据被当成指令）、agent 权限过大（一句被注入的话就能触发删除或外发数据），以及需要在模型的输入和输出两侧加上的 guardrails。左右两边的原则是一样的：区分数据和指令、最小权限、默认拒绝、纵深防御。区别在于，LLM 没有「参数化查询」这样能彻底解决注入的办法，只能靠多层缓解，并且把权限控制在模型之外。

- **应用安全：OWASP**：2025 版 Top 10，参数化与白名单，供应链锁定，安全地处理异常。
- **数据隐私与 PII**：最小化、数据地图、加密与假名化、跨所有副本的删除、LLM 的数据外流路径。
- **Prompt injection**：直接注入和间接注入，为什么防不住，怎么缓解。
- **Agent 权限与沙箱**：最小权限、按用户授权、沙箱执行、人工审批。
- **Guardrails**：输入和输出两侧的检查、内容安全、结构和事实校验。
