# 第 8 层：架构与权衡

这是最上面的一层：把下面八层的零件组合成一个系统，并且在性能、成本、复杂度、可靠性之间做取舍。这里没有新的机制，只有**判断**：服务边界怎么划，容量要准备多少，钱花在哪里最值。左边是传统后端架构的三个问题：服务边界（单体、微服务、模块化单体）、容量估算与高并发设计（用 Little's Law 和量级估算把需求变成资源）、成本（计算、存储、网络、人力）。右边是 AI 应用的三个架构决策：**交互模式**（同步聊天、流式、异步任务、后台 agent，各自对应不同的基础设施）、**模型分级与 batch**（用便宜的模型处理大部分请求，离线任务走五折的 batch 接口）、**自托管推理还是调 API**（什么时候值得自己运维 GPU）。面试里的系统设计题，考的就是这一层：给一个需求，能不能从约束出发，把下面各层的知识组合成一个说得清取舍的方案。

- **服务边界**：微服务主要解决组织规模问题；默认模块化单体，按扩展特征、发布节奏、团队、安全边界再拆。
- **容量估算与高并发设计**：QPS、并发数、存储、带宽的量级估算，读写分离、缓存、异步、分片的组合。
- **成本**：主要成本在哪，怎么度量，怎么优化。
- **同步 / 异步交互模式**：流式、轮询、回调、后台任务，各自适合什么场景。
- **模型分级与 batch**：路由、级联、蒸馏，以及离线批处理。
- **自托管推理还是调 API**：成本的盈亏平衡点、数据和合规、运维负担。
