# 第 1 层：接口

这一层是服务对外的**契约**：别人怎么调用你、谁有资格调用、出错和重试时语义是什么、长时间的输出怎么推给客户端。它建在第 0 层之上（HTTP 语义、TLS、长连接），又是所有上层能力的入口：存储、编排、网关都要通过这里暴露出去。左边是传统后端的四件事：API 设计、认证鉴权、幂等、流式。右边是 LLM 带来的两种新契约：一是**调模型**的契约，供应商 API 和结构化输出，要处理流式碎片、stop_reason、格式差异；二是**让模型调你**的契约，tool calling 和 MCP，对模型来说，tool schema 就是一份新的 API。这一层的共同主题是：契约要让调用方难以用错。调用方是人写的代码时如此，是一个会犯错的模型时更是如此。

- **API 设计与序列化**：REST / gRPC / GraphQL，兼容性规则，状态码会驱动客户端的自动行为。
- **认证与鉴权**：session vs JWT，OAuth + PKCE，API key 只存哈希；RAG 和 agent 要带着用户的权限执行。
- **幂等与错误语义**：哪些操作能安全重试，幂等 key 怎么实现。
- **流式接口**：SSE 和 WebSocket，代理缓冲，中途出错怎么办。
- **Provider API 与结构化输出**：多家供应商的格式差异、流式 tool call 拼接、JSON schema 约束。
- **Tool calling 与 MCP**：schema 即契约，工具出错要回传给模型而不是中断。
