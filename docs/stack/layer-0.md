# 第 0 层：地基

这一层是所有服务都跑在上面的东西，自己不依赖图上的任何其他层。左边是传统后端的地基：数据怎么在网络上走（TCP / HTTP / TLS）、操作系统怎么把 IO 交给程序（阻塞、epoll、IOCP）、程序怎么同时处理很多件事（线程、协程、锁）。右边是 LLM 作为一种新依赖的「物理特性」：按 token 计量、输出有随机性、生成过程分 prefill 和 decode 两段，所以它**慢、贵、不确定**。上面每一层的设计，几乎都能追溯到这两组约束：第 1 层的流式接口是因为 decode 慢，第 2 层的 prompt cache 是因为 prefill 贵，第 6 层的 eval 是因为输出不确定。

- **网络：TCP / HTTP / TLS**：延迟由 RTT 决定，连接复用是最便宜的优化。
- **OS 与 IO 模型**：少量线程管大量连接，readiness（epoll）和 completion（IOCP / io_uring）两种模型。
- **并发模型**：线程、事件循环、协程各自的成本，以及共享状态怎么保护。
- **Token 与上下文窗口**：LLM 的计量单位和内存上限。
- **采样、非确定性与幻觉**：为什么同一个 prompt 两次结果不一样，以及这对后端意味着什么。
- **延迟与成本模型**：TTFT 由 prefill 决定，吐字速度由 decode 决定，账单按输入、输出分别计价。
