# 第 2 层：数据与状态

这一层回答「状态放在哪、怎么查、怎么保证不丢不乱」。它建立在第 0 层之上：磁盘和 page cache 决定了为什么要用 B+ 树，fsync 决定了为什么要用 WAL，连接模型决定了为什么要用连接池。上层的编排（第 4 层）和分布式（第 5 层）都在处理「这一层的状态怎么跨任务、跨节点保持一致」。左边是传统后端的三件套：关系库（索引、事务、隔离级别）、缓存、NoSQL 与全文检索。右边是 LLM 应用新增的三种状态：**向量**（embedding 和近似最近邻索引，让「语义相近」变成可以查询的东西）、**会话记忆**（多轮对话和 agent 的长期记忆存在哪、以谁为准）、**prompt 缓存**（同一个前缀不要重复付 prefill 的钱）。一个值得注意的趋势是「一个 Postgres 装下所有东西」：DocPilot 把文档、chunk、全文索引、向量、会话和 trace 都放在同一个 Postgres 里，少一个系统就少一份一致性问题。

- **索引、事务与隔离级别**：B+ 树、WAL、MVCC，丢失更新和写偏斜，事务里不要调用外部服务。
- **缓存**：cache-aside 的写顺序，穿透 / 击穿 / 雪崩，只缓存成功的结果。
- **NoSQL 与全文检索**：LSM 树、KV / 文档 / 宽列存储，倒排索引与 BM25。
- **Embedding 与向量索引**：HNSW / IVF，召回率与延迟的权衡，带过滤条件的检索。
- **会话与记忆**：历史以服务端为准，短期上下文与长期记忆的分层。
- **Prompt caching 与语义缓存**：前缀缓存、exact cache 的 key 规范化、语义缓存的阈值和命名空间。
