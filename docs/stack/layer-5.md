# 第 5 层：分布式与韧性

一台机器放不下（数据量、吞吐）、挂不起（可用性）的时候，就要进入这一层：数据要复制、要分片，跨节点的操作要保持一致，依赖的服务出故障时系统还要能撑住。它建立在第 2 层（单机的存储与事务）和第 4 层（异步与编排）之上，Saga 就是一种带补偿的编排。左边是传统分布式系统的四个问题：复制与一致性（主从、quorum、CAP、Raft）、分片（怎么切、怎么扩容、热点怎么办）、分布式事务（为什么不用 2PC、Saga 怎么补偿）、韧性（限流、熔断、重试、超时）。右边只有一格，但很关键：**LLM 网关**。LLM 供应商就是一个慢、贵、会限流、偶尔大面积故障的外部依赖，网关上的路由、fallback、配额和限流，就是把左边的韧性模式一一套用到模型调用上。LLMGateway 的设计（只在首字节之前 fallback、预算耗尽回 402、Redis Lua 双令牌桶）是这一层最直接的实战素材。

- **复制与一致性**：同步 / 异步复制，复制延迟带来的异常，脑裂，CAP 的正确理解，Raft 选主和提交。
- **分片**：范围分片、哈希分片、一致性哈希，重新平衡，热点 key。
- **分布式事务与 Saga**：2PC 的问题，Saga 的补偿，TCC。
- **限流、熔断与重试**：令牌桶 / 漏桶，熔断器状态机，超时和 deadline 传播。
- **LLM 网关**：多供应商路由与 fallback、按 key 的限流和预算、流式请求的故障处理。
