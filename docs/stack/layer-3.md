# 第 3 层：上下文工程

这一层只有右边一组，标着「新增」：传统后端里没有对应的一层。它回答一个 LLM 应用特有的问题：**每一次调用时，模型应该看到什么**。模型是无状态的，它能做什么、做得多好，几乎完全取决于这一次上下文里放了什么。下面的第 2 层提供原料（向量索引、全文索引、会话记忆、prompt 缓存），这一层负责挑选、排序、压缩、格式化，然后交给第 4 层的 agent 循环一轮轮地使用。传统后端里与之最接近的是查询层（从存储里取出需要的数据），区别在于消费者不是确定性的代码，而是一个会受措辞、顺序和噪音影响的模型。所以这里的每个决定都要用 eval 来验证，而不能凭直觉。

- **Prompt 设计与版本管理**：prompt 是代码，进版本控制、评审、触发 eval；代码依赖的输出要设计成和 prompt 共享的常量或 schema。
- **RAG**：切分、混合检索、RRF 融合、重排、agentic 检索；检索和生成分开评估。
- **上下文压缩**：上下文超出预算或质量开始下降时，怎么摘要、裁剪、外置。
