# 第 6 层：运行与质量

这一层回答两个问题：**代码怎么可靠地上线**，以及**上线之后怎么知道它是好的**。它建立在下面所有层之上：要部署的是第 1–5 层构成的服务，要观测的是它们的延迟、错误、资源和成本。左边是传统的三件事：容器、K8s 与 CI/CD（不可变制品、健康检查、优雅关闭、兼容新旧代码的迁移）；可观测性（指标、日志、追踪，SLO 和错误预算）；渐进式发布（灰度、feature flag、自动回滚）。右边是 LLM 应用的新问题：**输出不确定，「好」不能再用「测试通过」来定义**。所以要有离线 eval（固定数据集 + 确定性检查 + LLM-as-judge），LLM tracing（每个回答是怎么来的、花了多少钱），以及线上回归和 A/B（prompt、模型、检索策略的改动在真实流量上效果如何）。左右两边的对应关系很直接：eval 之于 LLM，就像单元测试之于代码；LLM trace 是分布式追踪加上 token 和成本这两个维度；prompt 和模型的变更，同样要走灰度发布。

- **容器、K8s 与 CI/CD**：镜像最佳实践、存活和就绪探针、流式响应的优雅关闭、expand / contract 迁移。
- **可观测性**：RED / USE、直方图和分位数、标签基数、上下文传播、SLO 燃烧速率告警。
- **灰度与 feature flag**：金丝雀、蓝绿、按比例放量、自动回滚、flag 的生命周期。
- **离线 eval 与 LLM-as-judge**：数据集怎么建、指标怎么定、judge 怎么校准、CI 里怎么跑。
- **LLM tracing**：每个回答记录检索、工具调用、token、延迟、成本。
- **线上回归与 A/B**：线上的质量信号、对照实验、prompt 和模型的灰度。
